# Changelog

Все заметные изменения этого пакета фиксируются в этом файле.

Формат — по мотивам [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
нумерация версий — по [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 0.3.0

- **Split (2026-08-25): server only.** The library half — collection core (`MarketDataManager`),
  `MarketDataClient`, embedded source, wire protocol, domain types and the source contracts
  (`FeederSource`/`StreamLiveness`/`ManagedSource`/`SymbolLoadOutcome`) — moved to the published
  package `@solncebro/market-data-feeder-lib` (sibling repo `../market-data-feeder-lib`); this
  package is now `private: true` and consumes the library as a regular dependency. Deploy
  commands unchanged. Tests split: 24 unit files moved to the library, this repo keeps 12 unit +
  4 integration + `teardownDuringLoad` (wires the registry to the library's real manager).

## [0.2.0] - 2026-08-04

### Added

- **Встроенный источник данных (`createEmbeddedMarketDataSource` / `EmbeddedMarketDataSource`, `src/embedded/`)** — для приложения, которое является единственным потребителем рыночных данных на своей машине, отдельный процесс-фидер держит две копии одной и той же истории свечей (буфер сервера + зеркало клиента) и добавляет второй процесс Node с обменом по WebSocket/JSON. Новая фабрика поднимает то же ядро (`MarketDataManager`) прямо в процессе приложения — свою собственную `ExchangeConnector` (со сторожем свечей, настроенным как у автономного фидера, чтобы рыночные данные никогда не делили соединение с торговым путём хоста), свою очередь ограничения скорости запросов на дозагрузку и обёртку `EmbeddedMarketDataSource`, которая реализует тот же клиентский контракт `MarketDataSource` (чтение + события), что и `MarketDataClient` — переход приложения на встроенный источник не меняет код стратегии. Тишина биржевого потока транслируется в `connectionLost`/`connectionRestored`, `isStale()` переключается через 45 секунд молчания, часовая синхронизация листинга/делистинга держится собственным таймером адаптера. Первый потребитель — rubber (`MARKET_DATA_SOURCE=embedded`). (`src/embedded/embeddedMarketDataSource.ts`, `.types.ts`, `src/index.ts`)
- Константы сторожа свечей (`KLINE_WATCHDOG_GRACE_MS`, `KLINE_WATCHDOG_RECOVERY_COOLDOWN_MS`) и интервал синхронизации списка символов (`SYMBOL_LIST_SYNC_INTERVAL_MS`) вынесены в общий `src/domain/constants.ts` — теперь на одних значениях работают и автономный `FeederServer`, и встроенный адаптер, независимо от того, где размещено ядро. (`src/domain/constants.ts`)

## [0.1.0] - 2026-07-22

Первая версия фидера. Записана в changelog задним числом при подготовке 0.2.0 — до этого релиз не тегировался и changelog не вёлся; строки ниже сгруппированы по возможностям, а не по коммитам.

### Added

- **Сервер-фидер (`src/feeder.ts`, `FeederServer`)** — один процесс на биржу держит единственное подключение (`ExchangeConnector`) к бирже, грузит клайны **по требованию** (интервал/символ подгружается только когда его впервые запрашивает клиент, со счётчиком ссылок и отложенным освобождением через `SubscriptionRegistry`) и раздаёт поток нескольким приложениям-стратегиям по локальному WebSocket-каналу.
- **Клиент (`MarketDataClient`)** — зеркалирует поток в памяти, отдаёт тот же API чтения и события, что и внутрипроцессный менеджер рыночных данных, так что код стратегии не меняется при переходе на фидер. Самовосстановление при протухании данных (пересоздание транспорта), учёт свежести отдельно для потоков с высокой частотой событий и потоков только по закрытию свечи.
- **Скользящие средние и 24-часовой объём** — расчёт SMA (25/50/100/200) на каждой свече, фоновый опрос 24-часового объёма с рассылкой изменений подписчикам.
- **Самолечение потока данных** — обнаружение дыр в истории и локально "запечатанных" свечей без биржевого закрывающего кадра, дозагрузка недостающих свечей через REST с ограничением одновременных дозагрузок и охлаждением на символ; обнаружение символов с недогруженной историей (усечённая REST-дозагрузка) с защитой от ложного схлопывания порога и постепенным принятием короткой истории как биржевой правды после нескольких подтверждающих проверок.
- **Диагностика и самовосстановление (`src/health/`)** — сторож молчания потока (тишина по всему источнику ловится за секунды, а не по таймауту на символ), детектор массовой протухлости, guard от массового делистинга (подтверждение на второй синхронизации), дайджест по проблемным символам раз в 30 минут вместо алерта на каждое событие, автоматический перезапуск при затяжной деградации с файловым счётчиком попыток, переживающим сам перезапуск.
- **Telegram-бот управления и мониторинга (`src/telegram/`)** — обязательный компонент процесса: статус, список протухших символов, карточка символа, перезапуск без подтверждения; фоновый пробник доступности канала.
- **Защита канала** — валидация входящих сообщений на границе (интервал/scope/список символов/лимиты), эвристики против медленного/полумёртвого клиента (пинг-понг, лимит буфера на отправку), ограничение числа соединений и размера payload.
- **Фильтр TradFi-инструментов** — из вселенной символов исключаются токенизированные TradFi-перпетуалы (акции/ETF/сырьё), остаются только крипто-перпетуалы.
